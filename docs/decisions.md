# Design decisions

Short record of the choices behind the data pipeline and the viewer, and why they were made.

## Data cleaning (`scripts/build_data.py`)

- **The raw CSVs are never edited.** Cleaned copies go in `data/processed/`. The raw files are
  spreadsheet exports, and re-exporting should be enough to refresh everything.
- **Encoding:** the files are read as UTF-8 first, falling back to cp1252 (the CALS export is cp1252).
  Non-breaking spaces and `U+FFFD` replacement characters (from a bad copy-paste in the Rallython
  description) become ordinary spaces.
- **Junk columns:** only the 14 named header columns are kept. The University-Wide export had about
  16,000 trailing columns, because the Rallython row was pasted about 1,000 times to the right.
- Rows with no Program Name are dropped. "yes"/"high" are normalized to "Yes"/"High".
- **Unit merge:** "UVM-wide / Community-facing" is folded into "University-wide". They describe the
  same scope, and keeping both splits the hierarchy for no reason. Units like
  "Office of the Vice President of Research" stay as they are.
- **Name-only rows** (UVM Libraries, VACC, OSHER Center, and others) are kept so they show up on
  the map, but they get no keywords and are marked `Unknown`/`Unspecified` until someone researches them.
- **Known data issue:** in some rows, `Email` and `Program Link` contain hyperlink display text
  ("Catamount Farm CSA | Agriculture, Landscape, and...") instead of the URL. The export dropped
  the link targets. The viewer links only values that start with `http`.

## Enrichment (`prompts/enrich_assets.md` -> `data/processed/enrichment.json`)

- The enrichment is generated by following a saved, standardized prompt, not by an API call at
  build time. Its output is a hand-editable JSON file that the build merges into the processed CSVs. That
  keeps the build deterministic, and a person can review and edit every tag.
- **Keywords:** 5–10 per program, lowercase, singular, topical (what the program is about or does).
  Generic words (`uvm`, `vermont`, `program`, `research`, …) are banned because they match
  everything. The prompt asks to **reuse existing vocabulary** before coining new terms. Shared
  keywords are what connect programs when you click a keyword chip.
- **Audience** went from free text to 10 controlled values, multi-label (a program usually
  serves several groups), plus one `audience_primary` used for color. The 10 values were chosen
  to cover every phrase in "Who the Program Serves" while staying distinct. For example, "community
  members", "anyone", "households" and "gardeners" all become *General Public*. Farmers,
  growers, foresters, beekeepers and maple producers all become *Farmers & Producers*.
- **Region** is a single ordinal value (Campus/Burlington → Vermont → Regional → National/Intl).
  The prompt takes the **widest** scope the source states, so "Vermont statewide / regional" becomes
  Regional. Ordinal values let the viewer show reach as border weight.
- **Asset category:** the source had about 25 Asset Type variants ("Program", "Program ",
  "Extension testing service", …). They're consolidated to 8 categories so the "asset type" tier
  of the hierarchy has a few meaningful branches instead of one node per spelling. The original
  Asset Type is still shown in the detail panel.
- `tests/test_enrichment_schema.py` checks that every value is in the vocabularies documented in the
  prompt, so the prompt, the data and the viewer can't drift apart.

## Viewer (`web/`)

- **GitHub Pages + React instead of Streamlit.** Click-to-drill graph navigation, clickable keyword
  chips and per-node styling are awkward in Streamlit: each click reruns the whole script and the
  graph component redraws. With about 40 records, everything can run in the browser with no server.
  Python still owns all the data processing.
- **Cytoscape.js** for the graph (with dagre for top-down layout) and **Fuse.js** for fuzzy search
  over name (weight 3), keywords (2) and description (1). Multi-word queries are also matched one
  token at a time.
- **Hierarchy:** UVM → unit → asset category → program. Arrows show parent → child only. Any node
  with fewer than 3 children is expanded automatically, so small branches don't cost a click.
- **Color = audience, in 7 groups.** The 10 audience values are folded into 7 color groups
  (Students + UVM Faculty & Staff; Youth & Families + Educators & Schools;
  Government + Nonprofits), because past about 7–8 hues the colors can't be told apart reliably,
  especially for colorblind viewers. The palette was checked with a colorblind-safety validator.
  Colors are fixed per group, so filtering never repaints them. Every node also has a text label,
  and the detail panel lists the full (ungrouped) audience values.
- **Shape = node type** (hexagon UVM, rounded rectangle unit, tag category, ellipse program).
  **Border = region** (dotted campus, thin solid Vermont, thick solid regional, double
  national/intl, dashed unknown). Program nodes use a light tint of their audience color, so the
  dark label text stays readable. Category and unit nodes show a pie of their programs' audience mix.
